# 전략 분석·비교 보고서 개편 명세

## 1. 목적

기업 분석 페이지와 비교 페이지의 보고서를 사건 요약이 아니라 **사용자의 사업 판단을 돕는 분석 기능**으로 개편한다.

기업 분석 페이지에서는 같은 시계열을 세 가지 용도로 읽을 수 있게 한다.

1. 전략 방향
2. 패턴 인사이트
3. 전략 분기점

비교 페이지에는 `비교 리포트 생성` 버튼 하나만 둔다. 선택한 기업의 밸류체인 관계를 시스템이 판단하여 경쟁, 고객·공급, 또는 인접 소재 관점으로 분석한다.

보고서는 근거에 없는 사건을 만들지 않지만, 복수의 사실을 연결한 전략 해석과 사업적 파급 해석을 적극적으로 제공한다. 반복적인 유보 문구와 확인 과제 나열은 본문에서 제거한다.

---

## 2. 제품 결정

### 2.1 기업 분석 페이지

`시계열 리포트 생성`을 누르면 다음 세 옵션을 보여준다.

| 옵션 | 사용자의 질문 | 핵심 결과 |
| --- | --- | --- |
| 전략 방향 | 이 기업은 지금 어디에 무게를 두고 있으며 과거와 무엇이 달라졌는가? | 현재 전략 판단, 변화의 근거, 사업적 의미 |
| 패턴 인사이트 | 떨어져 있던 사건들을 연결하면 무엇이 새롭게 보이는가? | 최대 3개 패턴, 연결 근거, 한국 산업 함의 |
| 전략 분기점 | 현재 진행 중인 변화가 어떤 경로로 갈릴 수 있는가? | 핵심 갈림길, 경로별 의미, 판단을 바꾸는 신호 |

세 옵션은 하나의 보고서 안에 모두 들어가는 목차가 아니다. 사용자가 선택한 용도에 따라 **입력 근거의 선별 방식, 분석 질문, 출력 구조**가 달라진다.

### 2.2 비교 페이지

비교 페이지에는 `비교 리포트 생성` 버튼 하나만 둔다. 별도 관점 선택 UI를 두지 않는다.

| 기업 조합 | 자동 적용할 기본 관점 |
| --- | --- |
| 셀–셀 | 제품·고객·지역·생산 방식의 경쟁 관점 |
| 양극재–양극재 | 화학계·원가·성능·고객 채택·공급 능력의 경쟁 관점 |
| 음극재–음극재 | 천연·인조·실리콘계 포지션, 원가·성능·고객 채택의 경쟁 관점 |
| 셀–양극재 또는 셀–음극재 | 셀사의 수요·기술 요구와 소재사의 공급 적합성을 읽는 고객·공급 관점 |
| 양극재–음극재 | 같은 배터리 기술·수요 전환에 대응하는 인접 소재 관점 |

기업 조합만으로 결론을 고정하지 않는다. 실제 입력에 있는 제품, 화학계, 고객, 지역, 양산 단계에 따라 분석축을 조정한다.

## 3. 추론 허용 범위

### 3.1 허용하는 추론

보고서는 다음 두 영역까지 추론할 수 있다.

#### 전략 해석

- 복수 시점의 사건을 연결해 기업의 우선순위 변화를 해석한다.
- 기술개발, 고객 채택, 생산투자, 출하와 실적의 진행 순서를 읽는다.
- 서로 다른 사업·제품·지역의 비중 변화로 성장 방식의 전환을 해석한다.
- 여러 레이어가 같은 방향으로 움직이거나 서로 엇갈리는 패턴을 찾는다.

#### 사업적 파급 해석

- 관측된 기업 변화가 고객의 구매 기준과 소재 수요에 미칠 수 있는 영향을 설명한다.
- 기술·제품 전환이 경쟁 구도, 원가 압력, 공급망 위치에 미칠 수 있는 영향을 설명한다.
- 중국 기업의 변화가 한국 셀사·양극재사·음극재사에 주는 기회 또는 압박의 방향을 제시한다.
- 산업에서 일반적으로 성립하는 사업 메커니즘을 연결 고리로 사용할 수 있다.

예:

> 고밀도 LFP 제품의 양산과 해외 생산거점 확대가 함께 나타난다면, 가격 중심의 공급 확대보다 성능과 현지 공급 능력을 묶는 경쟁 방식으로 이동하는 흐름으로 읽을 수 있다. 이는 한국 LFP 소재사에 원가 외에도 고객 공정 적합성과 현지 공급 대응력을 요구하는 압력으로 이어진다.

### 3.2 허용하지 않는 추론

- 입력에 없는 계약, 고객, 공급 관계, 생산 또는 실적을 사실처럼 쓴다.
- 시간적으로 앞선 사건을 뒤 사건의 직접 원인으로 단정한다.
- 계획·협약·수주를 양산·출하·매출로 격상한다.
- 서로 다른 제품·고객·지역의 사건을 하나의 상업화 경로로 합친다.
- 비교 자료 없이 종합적인 기술 우위나 시장 지배력을 단정한다.
- 미래 매출, 점유율, 성공 확률을 임의로 수치화한다.
- 주가, 목표주가, 매수·매도 의견을 제시한다.

### 3.3 표현 원칙

보고서는 결론을 먼저 제시한다. 불확실성은 결론의 의미를 실제로 바꾸는 경우에만 해당 문장 가까이에 짧게 표시한다.

다음 표현을 반복하지 않는다.

- 확인이 필요하다
- 추가 검토가 필요하다
- 근거가 부족하다
- 판단하기 어렵다
- 지켜봐야 한다
- 대응해야 한다

자료가 약한 주제는 다음 중 하나로 처리한다.

1. 현재 근거로 내릴 수 있는 범위까지 결론을 좁힌다.
2. 결론을 바꾸는 조건을 구체적인 분기점으로 쓴다.
3. 사업적 의미가 없으면 해당 논점을 출력하지 않는다.

나쁜 예:

> 실제 출하 여부는 추가 확인이 필요하다.

좋은 예:

> 현재 움직임은 고객 채택 확대보다 생산 준비의 성격이 강하다. 후속 출하가 시작되면 평가의 중심은 준비 속도에서 실제 고객 확장성으로 이동한다.

## 4. 공통 입력 데이터

현재 기업 페이지의 화면 이벤트만 그대로 압축해서 보내는 방식은 패턴과 분기점 분석에 부족하다. 보고서 생성 시 서버가 상세 근거를 다시 구성한다.

### 4.1 필수 입력

```json
{
  "company": {
    "id": "company-id",
    "name_ko": "기업명",
    "type_tags": ["cell"]
  },
  "report_mode": "direction | pattern | inflection_point",
  "as_of_date": "2026-09-10",
  "events": [
    {
      "id": "event-id",
      "occurred_at": "2025-06-30",
      "occurred_precision": "day | month | half | year",
      "track": "market | technology",
      "layer_key": "customer-commercialization",
      "title_ko": "...",
      "fact_ko": "...",
      "entity_names": ["..."],
      "source_name": "...",
      "source_url": "...",
      "evidence_kind": "...",
      "timeline_eligibility": "core | reference",
      "object_key": "가능하면 제품·공장·고객 프로그램을 묶는 키",
      "stage": "가능하면 상업화 또는 실행 단계",
      "stage_status": "planned | confirmed | delayed | cancelled | unknown"
    }
  ],
  "metrics": [],
  "policies": [],
  "evidence_alternatives": []
}
```

`object_key`, `stage`, `stage_status`가 아직 DB에 없으면 초기 버전에서는 이벤트 제목·사실·추출 fact를 이용해 보고서 입력을 만들 때 임시 그룹을 생성한다. 임시 그룹은 DB의 원시 이벤트를 수정하지 않는다.

### 4.2 상업화·실행 단계

다음 단계는 관찰을 위한 공통 어휘로 사용한다.

```text
R&D
→ 성능 달성
→ 검증·인증
→ 고객 지정·채택
→ 수주·공급계약
→ 건설·생산 준비
→ 시험생산
→ 양산
→ 출하
→ 매출 기여
```

모든 기업과 제품이 이 순서를 그대로 거친다고 가정하지 않는다. 동일 제품·공장·고객 프로그램으로 연결 가능한 단계만 묶는다.

## 5. 용도별 근거 선별

### 5.1 전략 방향

우선순위:

1. 최근 3~4개 연간 정량 추이와 최신 누적 실적
2. 제품·사업·지역·고객 구성의 변화
3. 주요 투자와 실제 생산·출하 결과
4. 과거 방향과 최근 방향을 비교할 수 있는 사건
5. 전략 방향을 흔드는 반대 흐름

동일 연도의 대표 사건만 고르는 방식보다 **과거 상태와 최근 상태가 비교되는 묶음**을 우선한다.

### 5.2 패턴 인사이트

우선순위:

1. 동일 `object_key`의 앞뒤 사건
2. 서로 다른 레이어가 6~18개월 안에 같은 방향으로 움직인 사건
3. 반복적으로 나타난 선행·후행 순서
4. 계획·수주와 출하·매출 사이의 연결 또는 엇갈림
5. 최근 들어 반복 행동이 달라진 사건

탐색 패턴은 다음 네 개로 제한한다.

- Convergence: 여러 레이어가 같은 전략 방향으로 모임
- Lead-Lag: 특정 사건 뒤에 다른 사건이 반복적으로 나타남
- Gap / Divergence: 연결될 흐름이 관측상 끊기거나 반대 방향으로 움직임
- Inflection: 과거의 반복 행동이 최근 다른 방향으로 전환됨

패턴 이름은 내부 구조와 작은 배지에 사용할 수 있다. 사용자에게 보이는 제목은 결론형 한국어 문장으로 쓴다.

### 5.3 전략 분기점

우선순위:

1. 계획·건설·인증·고객 지정처럼 진행 중인 주요 사건
2. 이미 선행 단계가 있고 후속 단계에 따라 의미가 달라지는 제품·사업
3. 서로 다른 경로가 동시에 진행되는 사업 포트폴리오
4. 실적·생산·고객 변화가 전략 판단을 바꿀 수 있는 경계
5. 정책 시행이 특정 제품·지역 전략의 경제성을 바꿀 수 있는 경우

분기점은 할 일 목록이 아니다. 다음 구조로 작성한다.

```text
현재 위치
→ 경로 A가 현실화될 때의 전략적 의미
→ 경로 B가 이어질 때의 전략적 의미
→ 두 경로를 가르는 관측 신호
```

경로는 미래를 예언하는 시나리오가 아니라, 이미 관측된 움직임에서 직접 이어질 수 있는 조건부 해석이어야 한다.

## 6. 기업 분석 보고서 출력 구조

### 6.1 전략 방향 보고서

```text
# 전략 방향

## 현재 판단
가장 중요한 전략 변화와 현재 방향을 2문장 이내로 제시

## 방향을 만든 변화
최대 3개
- 결론형 제목
- 과거 → 현재 변화
- 핵심 근거
- 사업적 의미

## 한국 산업에 주는 의미
관련성이 있을 때 최대 2개

## 근거
본문 판단에 사용한 사건·수치·출처
```

### 6.2 패턴 인사이트 보고서

```text
# 패턴 인사이트

## Strategic Thesis
전체 시계열을 관통하는 연결을 2문장 이내로 제시

## Top Patterns
최대 3개, 유의미한 패턴 수만 출력
- 패턴 유형
- 결론형 제목
- 발견한 연결
- 핵심 근거 2~4개
- 사업적 의미
- 결론을 실질적으로 약화하는 상충 사실이 있으면 짧게 병기

## 한국 산업에 주는 의미
관련성이 있을 때 최대 2개

## 근거
사용한 사건·수치·출처
```

### 6.3 전략 분기점 보고서

```text
# 전략 분기점

## 현재 위치
기업이 어느 갈림길에 있는지 2문장 이내로 제시

## 핵심 분기점
최대 3개
- 결론형 제목
- 현재까지 진행된 경로
- 경로 A와 사업적 의미
- 경로 B와 사업적 의미
- 판단을 바꾸는 구체적 신호

## 한국 산업에 주는 의미
각 경로가 한국 셀·소재 부문에 주는 차이를 최대 2개

## 근거
사용한 사건·수치·출처
```

## 7. 비교 보고서 자동 관점

### 7.1 관점 결정 규칙

서버가 회사의 `type_tags`로 기본 관점을 정하고, 실제 근거로 세부 축을 결정한다.

```text
같은 밸류체인
→ 경쟁 관점

셀 + 소재
→ 고객·공급 관점

서로 다른 소재
→ 인접 소재·공통 수요 관점
```

#### 경쟁 관점

- 같은 수요를 어떤 제품과 공급 방식으로 공략하는가?
- 제품·기술의 상업화 속도는 어떻게 다른가?
- 고객·지역·생산거점 전략은 어디서 갈리는가?
- 규모, 수익성, 기술 경로 중 실제 차별화 축은 무엇인가?

서로 다른 화학계나 시장을 중심으로 하는 기업은 직접 우열보다 포지션 경쟁으로 읽는다.

#### 고객·공급 관점

- 셀사의 제품·기술·생산 변화가 어떤 소재 요구를 만든다고 볼 수 있는가?
- 소재사의 기술·양산·지역 역량은 그 요구에 어디까지 맞는가?
- 공급 기회, 내재화 압력, 성능·원가 요구가 어떻게 작동할 수 있는가?
- 실제 거래 관계가 입력에 없더라도 산업의 고객·공급 구조는 분석할 수 있다.

실제 공급 관계가 없는 경우 `공급 중`, `고객사`라고 표현하지 않는다. 제품·기술 요구의 적합성과 사업 기회의 방향으로 쓴다.

#### 인접 소재 관점

- 같은 셀 기술 전환에서 각 소재가 받는 요구는 무엇인가?
- 수요 확대 시점과 양산 대응 시점이 맞물리는가?
- 한쪽의 변화가 다른 소재의 채택 조건을 바꾸는가?

### 7.2 비교 보고서 출력

```text
# 비교 판단

## 한눈에 보는 차이
적용 관점과 가장 중요한 차이를 2문장 이내로 제시

## 핵심 비교 논점
최대 3개
- 결론형 제목
- 두 기업의 관측 차이
- 그 차이가 생기는 전략·고객·공급 메커니즘
- 사업적 의미

## 한국 산업에 주는 의미
관련 사업 부문별 기회·압박·중립 방향을 최대 3개

## 판단이 달라지는 지점
비교 결론을 실제로 바꿀 수 있는 관측만 최대 2개

## 근거
사용한 사건·수치·출처
```

## 8. 공통 LLM 프롬프트

```text
[ROLE]

당신은 중국 배터리 셀·양극재·음극재 기업을 분석하는
Strategic Intelligence Analyst다.

독자는 한국 배터리 셀사와 양극재·음극재 소재사의
전략·시장조사·기술기획 담당자다.

[CORE OBJECTIVE]

입력된 정량 시계열, 시장·기술 이벤트, 정책과 출처를 이용해
사용자가 기업의 방향과 사업적 의미를 판단할 수 있는 분석을 작성하라.

사건을 다시 요약하는 데 머물지 마라.
복수 시점과 복수 레이어의 사실을 연결해 변화의 방향,
상업화 진행, 전략의 이동, 경쟁·고객·공급망 파급을 해석하라.

[INFERENCE POLICY]

다음을 허용한다.

1. 복수 사실을 연결한 전략 해석
2. 관측된 전략 변화에서 이어지는 사업적 파급 해석
3. 산업에서 일반적으로 성립하는 고객·공급·경쟁 메커니즘의 적용
4. 관측된 진행 경로를 바탕으로 한 조건부 분기 해석

다음을 지킨다.

1. 입력에 없는 사건·수치·거래·고객을 사실처럼 만들지 않는다.
2. 계획·협약·수주·인증·양산·출하·매출 기여를 서로 구분한다.
3. 서로 다른 제품·고객·지역의 사건을 하나의 경로로 합치지 않는다.
4. 시간적 선후만으로 직접 인과를 단정하지 않는다.
5. 비교 가능한 기간·단위·사업 범위의 수치만 직접 비교한다.
6. 주가·목표주가·매수·매도 의견을 작성하지 않는다.

[WRITING POLICY]

결론을 먼저 쓴다.
가능한 방향이 보이면 유리·압박·전환·정체·확대·축소 중
입력이 지지하는 방향을 분명하게 표현한다.

'확인이 필요하다', '추가 검토가 필요하다', '근거가 부족하다',
'판단하기 어렵다', '지켜봐야 한다', '대응해야 한다'를 반복하지 마라.

자료가 약하면 현재 근거로 말할 수 있는 범위까지 결론을 좁혀라.
결론을 바꿀 조건이 중요하면 구체적인 전략 분기점으로 표현하라.
사업적 의미가 없는 약한 논점은 출력하지 마라.

불확실성과 상충 근거는 결론을 실제로 바꾸는 경우에만
해당 결론 가까이에 한 문장 이내로 쓴다.

한 사건이나 수치를 여러 섹션에서 반복하지 마라.
항목명 대신 무엇이 달라졌는지를 설명하는 결론형 제목을 사용하라.
사용자에게 보이는 문장은 자연스러운 한국어로 쓴다.

[EVIDENCE]

각 핵심 결론은 입력의 사건 또는 정량 근거에 연결되어야 한다.
근거는 결론을 설명할 만큼 구체적으로 쓰되 본문을 출처 목록으로 만들지 마라.
자세한 사건·수치·출처는 마지막 근거 절에 모은다.

최종 결과에는 요청한 보고서만 출력한다.
```

## 9. 전략 방향 전용 프롬프트

공통 프롬프트 뒤에 추가한다.

```text
[REPORT MODE: STRATEGIC DIRECTION]

이 보고서의 질문은 다음과 같다.

"이 기업은 지금 어디에 무게를 두고 있으며,
과거와 비교해 성장 방식과 전략 중심이 어떻게 달라졌는가?"

먼저 정량 시계열에서 규모·수익성·물량의 방향을 읽어라.
그 다음 제품, 고객, 지역, 생산투자, 기술의 사건을 연결해
무엇이 그 방향을 만들었는지 설명하라.

단순히 최근 사건을 중요 전략으로 부르지 마라.
과거 상태와 최근 상태의 차이, 자원의 이동, 실행 단계의 진전을 근거로 판단하라.

핵심 변화는 최대 3개만 선택한다.
각 변화는 다음 흐름으로 쓴다.

과거 상태
→ 현재 달라진 점
→ 그 변화가 보여주는 전략 방향
→ 기업과 한국 배터리 산업에 갖는 의미

출력 순서:

# 전략 방향
## 현재 판단
## 방향을 만든 변화
## 한국 산업에 주는 의미
## 근거
```

## 10. 패턴 인사이트 전용 프롬프트

```text
[REPORT MODE: PATTERN INSIGHT]

이 보고서의 질문은 다음과 같다.

"개별 사건을 하나씩 읽었을 때는 보이지 않지만,
시간축과 시장·기술·정책·실적을 연결하면 무엇이 드러나는가?"

다음 패턴을 탐색한다.

1. CONVERGENCE
   서로 다른 레이어가 비슷한 시기에 같은 전략 방향을 가리킴

2. LEAD-LAG
   동일 제품·사업에서 한 종류의 사건 뒤에 다른 단계가 이어짐

3. GAP / DIVERGENCE
   기대되는 연결이 관측상 끊기거나 서로 다른 방향으로 움직임

4. INFLECTION
   과거의 반복 행동이 최근 다른 방향으로 바뀜

단일 사건은 패턴이 아니다.
최소 두 시점 또는 두 레이어를 연결해야 한다.
동일 원출처에서 파생된 여러 문장을 독립 근거 여러 개처럼 세지 마라.

패턴을 억지로 모두 만들지 마라.
서로 같은 결론을 다른 패턴 이름으로 반복하지 마라.
유의미한 패턴이 한 개면 한 개만 출력한다.

각 패턴은 다음에 답해야 한다.

- 무엇이 함께 움직이거나 갈라졌는가?
- 왜 개별 사건만 읽을 때는 보이지 않았는가?
- 기업의 성장 방식·상업화·경쟁력·리스크에 어떤 의미가 있는가?
- 한국 셀·소재 사업에는 어떤 압력 또는 기회로 이어지는가?

'왜 보이지 않았는가'는 별도 형식 문구로 반복하지 말고
패턴 설명 안에서 자연스럽게 드러내라.

출력 순서:

# 패턴 인사이트
## Strategic Thesis
## Top Patterns
## 한국 산업에 주는 의미
## 근거
```

## 11. 전략 분기점 전용 프롬프트

```text
[REPORT MODE: STRATEGIC INFLECTION POINT]

이 보고서의 질문은 다음과 같다.

"현재 진행 중인 변화가 어떤 경로로 갈릴 수 있으며,
각 경로는 기업의 성장 방식과 한국 배터리 산업에 무엇을 의미하는가?"

분기점은 아직 끝나지 않은 중요한 움직임에서 찾는다.
계획, 고객 지정, 인증, 건설, 시험생산, 제품 전환,
해외 거점, 수익성 변화처럼 후속 전개에 따라 의미가 달라지는 사건을 우선한다.

미래를 임의로 예측하지 마라.
이미 입력에 나타난 진행 경로에서 직접 이어지는 조건만 사용한다.

각 분기점은 다음 구조로 쓴다.

1. 현재 위치: 지금까지 어떤 단계가 관측됐는가?
2. 경로 A: 다음 단계가 이어지면 전략 판단이 어떻게 바뀌는가?
3. 경로 B: 정체·축소·다른 방향이 나타나면 판단이 어떻게 바뀌는가?
4. 분기 신호: 두 경로를 가르는 구체적인 사건 또는 수치는 무엇인가?

분기 신호를 '확인할 사항'이나 할 일처럼 쓰지 마라.
신호가 나타났을 때 전략 해석이 어떻게 달라지는지를 함께 써라.

분기점은 최대 3개만 선택한다.
서로 독립적인 전략 판단을 바꾸는 분기점만 남긴다.

출력 순서:

# 전략 분기점
## 현재 위치
## 핵심 분기점
## 한국 산업에 주는 의미
## 근거
```

## 12. 비교 보고서 전용 프롬프트

```text
[REPORT MODE: ADAPTIVE COMPANY COMPARISON]

두 기업의 밸류체인 위치와 실제 입력 근거를 읽고
가장 유용한 비교 관점을 자동으로 선택하라.

같은 밸류체인이면 경쟁 관점을 기본으로 한다.
셀사와 소재사 조합이면 고객·공급 관점을 기본으로 한다.
서로 다른 소재 조합이면 같은 셀 기술·수요 전환에 대응하는
인접 소재 관점을 기본으로 한다.

보고서 첫머리에 적용한 관점을 한 문장으로 자연스럽게 밝힌다.
내부 분류 코드나 분석 모드 이름은 쓰지 않는다.

[경쟁 관점]

- 두 기업이 어떤 제품·시장·고객·지역에서 경쟁하는가?
- 상업화 단계와 공급 방식은 어떻게 다른가?
- 규모·원가·성능·고객 채택·해외 대응 중 실제 차별화 축은 무엇인가?
- 서로 다른 시장을 공략하면 직접 우열보다 포지션 차이를 설명하라.

[고객·공급 관점]

- 셀사의 제품·기술·생산 전략이 어떤 소재 요구를 만드는가?
- 소재사의 기술·제품·양산·지역 역량이 그 요구와 어디에서 맞거나 엇갈리는가?
- 이 조합이 공급 기회, 원가·성능 압력, 내재화 또는 공급망 다변화에 어떤 의미가 있는가?
- 실제 거래가 입력에 없더라도 고객 요구와 공급 적합성은 분석할 수 있다.
- 실제 거래가 없으면 공급 중이거나 고객사라고 표현하지 마라.

[인접 소재 관점]

- 같은 배터리 수요·기술 전환이 두 소재에 어떤 다른 요구를 만드는가?
- 각 기업의 상업화와 공급 확대 시점은 어떻게 맞물리는가?
- 한쪽 소재 변화가 다른 소재의 채택 조건에 어떤 영향을 줄 수 있는가?

각 회사의 연혁을 따로 길게 요약한 뒤 다시 비교하지 마라.
처음부터 두 기업의 중요한 차이를 중심으로 구성한다.

핵심 비교 논점은 최대 3개만 선택한다.
각 논점은 다음 흐름으로 쓴다.

두 기업의 관측 차이
→ 차이를 만드는 전략·고객·공급 메커니즘
→ 두 기업과 한국 산업에 갖는 의미

한국 산업에 대한 해석은 기회와 위협을 기계적으로 모두 만들지 않는다.
입력이 지지하는 방향을 셀·양극재·음극재 사업 부문 단위로 분명히 쓴다.

출력 순서:

# 비교 판단
## 한눈에 보는 차이
## 핵심 비교 논점
## 한국 산업에 주는 의미
## 판단이 달라지는 지점
## 근거
```

## 13. 화면 동작

### 13.1 분석 페이지

`시계열 리포트 생성` 버튼을 누르면 작은 선택 메뉴 또는 모달을 연다.

```text
어떤 관점으로 분석할까요?

[전략 방향]
기업의 성장 방식과 중심축 변화

[패턴 인사이트]
시장·기술·정책·실적 사이의 연결

[전략 분기점]
진행 중인 변화가 갈릴 경로와 사업적 의미
```

정책 포함 여부와 보조 데이터 포함 여부는 보고서 용도 선택 이후의 보조 설정으로 유지한다. 세 용도를 별도 버튼 세 개로 화면에 항상 노출하지 않는다.

### 13.2 비교 페이지

버튼은 현재처럼 하나다.

```text
[비교 리포트 생성]
```

생성 중 문구는 선택 기업의 관계에 따라 달라질 수 있다.

- 동종 기업: 경쟁 방식과 차별화 축을 분석 중
- 셀–소재: 고객 요구와 공급 적합성을 분석 중
- 인접 소재: 공통 수요와 기술 전환의 연결을 분석 중

## 14. 구현 계획

### Phase 1. 보고서 모드와 공통 정책

- `CLAUDE.md`의 해석 허용 예외에 기업 분석·비교 보고서를 추가한다.
- `timeline_report` 요청에 `reportMode`를 추가한다.
- 허용값은 `direction`, `pattern`, `inflection_point`로 제한한다.
- 공통 프롬프트와 모드별 프롬프트를 코드에서 분리한다.
- 기존 자유형 Markdown 반환은 유지하되 모드별 제목 구조를 검사한다.

### Phase 2. 분석 페이지 UI

- `시계열 리포트 생성` 클릭 시 세 옵션 선택 UI를 표시한다.
- 선택값을 API 요청에 전달한다.
- 생성 중 문구와 보고서 제목을 모드에 맞게 표시한다.
- HTML 저장 파일명에 보고서 모드를 포함한다.

### Phase 3. 용도별 입력 구성

- 공통 이벤트 24건 선별을 모드별 선별 함수로 분리한다.
- 날짜 정밀도, 근거 종류, 레이어와 상세 fact를 서버 입력에 보존한다.
- 패턴 모드는 동일 제품·사업의 앞뒤 사건을 함께 선택한다.
- 분기점 모드는 계획·인증·건설·시험생산 등 진행 중 사건과 그 선행 근거를 보존한다.
- 전략 방향 모드는 정량 추이와 제품·지역·고객·투자의 구성 변화를 우선한다.

### Phase 4. 비교 보고서 자동 관점

- 현재 `pairContext()`의 밸류체인 분류를 관점 라우팅에 사용한다.
- 셀–소재를 고객·공급 관점으로 명시한다.
- 동종 기업은 경쟁 관점으로, 서로 다른 소재는 인접 소재 관점으로 전달한다.
- 기존 A 궤적/B 궤적/재비교의 반복 구조를 비교 논점 중심 구조로 바꾼다.
- 화면 버튼은 하나만 유지한다.
- 선택된 분석 관점을 비교 리포트 히스토리에 저장한다.

### Phase 5. 출력 정리

- `data_gaps_ko`, `counter_hypothesis_ko`, `limits_ko` 같은 필수 유보 필드를 본문 필수값에서 제거한다.
- 결론을 바꾸는 상충 근거만 해당 논점에 선택적으로 붙인다.
- 검증 상세, 교정 내역과 전체 출처는 펼쳐 보는 근거 영역에 둔다.
- `[사실]`, `[추론]`, `[교차추론]`, `[미확보]`를 매 문장 앞에 반복하는 규칙을 제거한다.

### Phase 6. 평가와 회귀검사

셀·양극재·음극재에서 대표 기업을 최소 한 곳씩 선택한다.

분석 페이지 평가:

- 같은 기업에서 세 모드의 중심 결론이 실제로 다른가?
- 전략 방향은 과거와 최근의 변화를 설명하는가?
- 패턴 인사이트는 두 시점 또는 두 레이어 이상을 연결하는가?
- 전략 분기점은 할 일 목록 대신 경로별 의미를 설명하는가?

비교 페이지 평가:

- 셀–셀에서 경쟁축이 드러나는가?
- 양극재–양극재에서 제품·화학계·고객·공급 차이를 읽는가?
- 셀–양극재에서 고객 요구와 공급 적합성을 설명하는가?
- 실제 거래가 없는 기업을 거래 관계로 표현하지 않는가?
- 한국 산업 함의가 단순 사실 반복을 넘는가?

공통 평가:

- 입력에 없는 수치·고객·계약을 만들지 않는가?
- `확인 필요`, `근거 부족` 같은 유보 문구가 본문을 지배하지 않는가?
- 동일 사건과 결론을 여러 섹션에서 반복하지 않는가?
- 근거 상세를 열면 핵심 결론의 출처를 추적할 수 있는가?

## 15. Acceptance Criteria

1. 분석 페이지는 보고서 생성 시 세 용도 중 하나를 선택할 수 있다.
2. 세 용도는 서로 다른 프롬프트와 근거 선별 정책을 사용한다.
3. 비교 페이지에는 보고서 생성 버튼이 하나만 존재한다.
4. 비교 보고서는 기업 조합에 따라 경쟁, 고객·공급, 인접 소재 관점을 자동 적용한다.
5. 분석·비교 보고서는 전략 해석과 사업적 파급 해석을 제공한다.
6. 핵심 논점은 최대 3개이며 의미 없는 항목을 억지로 채우지 않는다.
7. 반복적인 유보 문구와 확인 과제 목록을 본문에 출력하지 않는다.
8. 분기점은 관측 신호와 함께 판단이 어떻게 달라지는지를 설명한다.
9. 셀–소재 비교는 실제 거래가 없어도 고객 요구와 공급 적합성을 분석한다.
10. 실제 거래 근거가 없으면 고객사·공급사 관계를 사실처럼 표현하지 않는다.
11. 모든 핵심 결론은 입력 근거로 추적할 수 있다.
12. 사실 데이터와 보고서 해석은 별도 영역으로 유지한다.
13. 투자 의견과 근거 없는 정량 예측은 출력하지 않는다.

## 16. 이번 개편에서 하지 않는 것

- 원시 `event`를 패턴 결과로 덮어쓰기
- 모든 패턴 결과의 DB 영속화
- 복잡한 확률 기반 미래 시나리오
- 자동 전략 Option 또는 실행 과제 생성
- 경쟁사 전체 자동 벤치마크
- 투자 의견 생성

보고서의 유용성이 실제 평가에서 확인된 뒤, 반복적으로 가치가 있는 패턴만 별도 구조화·저장하는 후속 단계를 결정한다.

# 중국 정책 시간축

2026-09-10 사용자 요청: Daily에 배터리·NEV·ESS 정책 수집 추가, 과거는 첨부만 사용, 기업 분석·비교의 시간축과 LLM 보고서에 공통 정책 변수 포함.

첨부 `compass_artifact_wf-1d8db676-f890-53ad-a9b4-44aa39ebef1f_text_markdown.md`의 6개 축 마스터 테이블 35건을 `lib/policy-history.js`로 구조화했다. 첨부의 Recommendations와 소재 산업 함의는 근거 사실로 옮기지 않았다. 발표·시행 원표기, 문건번호, 부처, 첨부 작성자의 검증 표기를 보존한다. 독립적인 원문 검증을 수행한 것은 아니므로 화면·보고서에 사용자 참고자료로 표시한다. 불완전한 URL을 추정해 만들지 않았다.

`lib/policy-context.js`가 발표 시점과 명시된 시행·유예 일정을 각각 시간축 항목으로 만든다. 월·연 단위 날짜는 정렬을 위해 1일로 정규화하고 화면에는 원래 정밀도로 표시한다. 일정이 지났다는 이유로 현행 효력이 확인됐다고 판단하지 않는다. 과거 자료는 배포 파일에 포함되므로 SQL·과거 웹 백필이 필요 없다.

일일 수집에서는 제공자당 정책 검색 1회를 추가하고 최근 3일의 신규 자료만 허용한다. 날짜 미상·기간 외·비HTTP URL은 버린다. 별칭에 기업이 없어도 내부 분류 ID `china-policy`로 `article_company`에 연결하며, 기업 선택 목록에는 이 ID를 노출하지 않는다. 기존 스키마를 재사용하고 수집 때 이 분류 행을 멱등 생성한다. 정책 본문 후보는 훅당 최대 4건을 기업 Top 10과 별도로 먼저 처리한다. 기존 본문 대조·한국어 요약·임베딩·Daily 경로를 거친다.

기업 API는 첨부 연혁과 전역 정책 이벤트를 함께 반환한다. 회사의 보조 데이터 토글은 공통 정책축을 숨기지 않는다. 기업 시간축의 정책 열, 비교 공통 시간축, 전체 정책 목록에서 같은 자료를 본다. 두 보고서 경로는 서버에서 같은 정책 집합을 읽으며, 비교 보고서에는 정책 분석과 당시 근거 스냅샷을 저장한다. LLM은 적용 대상·시점·기업 근거를 함께 검토하고 인과를 단정하지 않도록 지시한다.

운영 반영에는 코드 배포가 필요하다. 이 작업에서 운영 수집이나 유료 LLM 호출은 실행하지 않았다.

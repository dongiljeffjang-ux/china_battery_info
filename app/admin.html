최근 실행

자동 감사 후보 · 기사 제목·요약의 회사명과 저장된 회사 연결, 기사→이벤트→청크 관계를 전수 대조합니다. 이름이 없는 기사는 정상일 수도 있으므로 자동 수정하지 않으며, 원문을 확인한 뒤 판단해야 합니다.
파이프라인이 단계마다 남긴 기록입니다. 이 기록은 admin-observability.sql 적용 이후 실행부터 쌓입니다.
청크의 content_ko가 실제 임베딩에 들어간 텍스트입니다. 기사 청크는 한국어 요약 헤더 + 원문 조각입니다.

이 화면의 숫자와 프롬프트는 실제 실행 코드에서 직접 읽습니다. 화면용으로 따로 적어 둔 값이 아니므로 코드가 바뀌면 여기도 함께 바뀝니다.

보고서 추출 dry-run · 고정된 표본 보고서를 현재 추출기에서 다시 읽어 반환·탈락·시점 정밀도를 확인합니다. 이벤트·청크·장부와 LLM 실행 로그에는 쓰지 않지만, 보고서당 LLM 호출 비용은 발생합니다.

비교·질의응답이 근거로 쓰는 벡터 검색을 답변 생성 없이 그대로 봅니다. 유사도는 코사인 기준이며 1에 가까울수록 가깝습니다.

평가 저장소가 아직 없습니다. supabase/rag-evaluation.sql을 Supabase SQL Editor에서 실행하면 판정을 저장할 수 있습니다. 실행 전에도 목록과 검색은 볼 수 있지만 저장은 실패합니다.

벡터DB에 들어간 청크를 하나씩 보고 근거로 쓸 만한지 판정합니다. 판정을 누르면 바로 저장되고, 사유 태그와 메모를 바꾸면 다시 저장됩니다. 이 판정으로 청크를 자동 삭제하지 않습니다.

질문을 던져 하이브리드 검색이 돌려준 근거를 순위째로 놓고 그 질문에 맞는 근거인지 판정합니다. 청크 품질과는 다른 실패를 봅니다 — 청크는 멀쩡한데 질문에 안 맞는 것이 올라오는 경우입니다.

사람이 검토한 질문·기준 답변·정답 청크를 저장합니다. 무료 검색 지표와 RAGAS 실행은 이 세트만 사용합니다.
